# 包装功能业务契约

这份参考用于快速核对 X.bot 包装功能的稳定行为。若与当前有效决策、核心项目文档或代码实测冲突，以项目事实来源优先级为准并指出差异。

## 触发与召回

- 新查询必须明确 `@X.bot`，私聊与群聊一致。
- 支持文本与带文字的飞书 `post`；项目正式名和别名优先，类型与标签用于缩小候选。
- 首批类型由集中配置维护：信息条、视频框、背景、分镜排版、分Part板、报道、时间轴。
- “人名条”“标注”“小标注”等受控别名规范化为“信息条”；“框”等受控表达可归入视频框。
- 未知项目只返回当前可查项目列表与示例，不创建查询状态。
- 纯图片不做视觉识别，不下载图片，不外发外部 AI；群聊保持低噪音。

## 候选与确认

- 单候选和多候选都使用一条 `post` 富文本消息，最多 3 个候选。
- 候选消息 ID 是唯一交互入口；确认、拒绝、编号选择和类型追问都必须回复该消息。
- 无 `reply_to` 时禁止查询最近 pending 记录或继承语境。
- 只有原查询人可以确认。默认有效期 20 分钟，多条查询互不取消。
- 明确的新 `@X.bot + 项目 + 包装意图` 查询不能被旧 pending 查询截获。

## 交付

- 常规包装必须有唯一 PNG + ZIP 配对；预览后确认，再发送源文件。
- 源文件是包含 AEP 与依赖的 ZIP，不发送裸 AEP。
- 小文件回复到最初查询消息；超过飞书消息接口限制时上传 bot 云盘并回复链接。
- 交付由数据库 claim/状态与飞书 idempotency key 双重防重；失败保留可重试状态。
- 仅图片背景只有 PNG，展示后即结束，不创建确认与源文件发送记录。

## 关键状态

- 查询状态按 `preparing -> pending -> sending -> completed` 推进，也可能进入 `expired`、`cancelled` 或 `failed`。
- 候选消息、最初查询消息、查询人和候选位置都必须稳定关联。
- 插件入库事件按 `event_id` 幂等消费；索引刷新失败时不能把事件误标为完成。

## 不可破坏边界

- 不直接写 Eagle `.library` 内部元数据。
- 不依赖文件同名建立唯一配对。
- 不在未经用户明确许可时把图片发送到外部 AI。
- 不绕过原查询人确认，不因模型判断直接发送 ZIP。
- 不提交素材、运行数据库、日志、PID、密钥或 Token。

## 验收示例

| 输入或场景 | 预期行为 |
| --- | --- |
| `@X.bot 找阿宝的信息条` | 返回阿宝信息条候选富文本，不直接发 ZIP |
| `@X.bot 有哪些项目可以查` | 返回当前有可用包装的正式项目列表 |
| 未回复候选直接发送 `第二个` | 不关联历史候选，不发送源文件 |
| 原查询人回复候选 `第二个` | 精确选择第 2 个候选并进入幂等交付 |
| 其他人回复候选 `确认` | 拒绝代确认，不发送源文件 |
| 回复已过期候选 | 提示重新查询，不污染其他 pending 查询 |
| 查询仅图片背景 | 返回 PNG 并说明无工程 ZIP，不创建确认状态 |
| 群里普通图片且未 @/未回复 bot | 不回应、不下载、不外发 |
