## 这是什么项目
X.bot 包装素材检索：在飞书里按项目名/别名/包装类型/标签检索 Eagle 素材。
机器人先回复静态 PNG 候选，原查询人在候选消息下回复确认后，才把对应 AE 源文件 ZIP 发回原消息。

## 模块地图
- `bot/` X.bot 监听器、Eagle 索引同步、包装检索服务（`lib/packaging-service.js` 是候选→确认→发送核心）。
- `aep-collector/` 第五阶段 AEP Worker 与兼容外部工具：不启动 AE 主界面，直接解析 AEP，按选中合成安全收集、生成独立 PNG/ZIP + manifest（Windows，`XbotAepWorker.exe` / `XbotAepCollector.exe`）。
- `ae-tool/` 已取代的 AE ScriptUI 方案，其可复用预览/manifest 代码仍保留。
- `eagle-plugin/` 第五阶段 Eagle 收集与入库助手插件（窗口工作台 + 本机 AEP Worker 桥接 + 扫描引擎 + API 导入层）。
- `skills/xbot-packaging-assets/` 飞书 X.bot 包装功能的可复用 Codex skill，覆盖维护、运行、诊断、查询确认契约和验证入口。
- `migrations/` SQLite 迁移；`tests/` 自动化测试。

## 数据与安全边界（必须遵守）
- 只能经 Eagle API 改数据，绝不直接改 `.library` 内的 `metadata.json`。
- Eagle 存素材；单机 SQLite 或多终端中央索引服务管理项目/包装/版本/预览/源文件稳定映射；不靠同名文件建立唯一关系。
- 多终端插件只能通过 Eagle 官方 Plugin API 写共享 Library，中央服务是共享索引的唯一数据库写入方；客户端不得通过 SMB/NAS 直接打开 SQLite。
- 不入库也不提交：`.library`、`.aep`、ZIP 源文件、SQLite 运行库、日志、密钥、API Token。
- 图片发外部 AI 前必须用户明确许可；机器人发源文件前必须原查询人确认且幂等。
- 源文件始终发 ZIP（含工程与依赖），不发裸 `.aep`。
- 测试遵循精简、精准原则，只覆盖新增行为、关键边界和回归风险。
